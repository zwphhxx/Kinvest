# 家庭投资看板设计说明

日期：2026-07-28  
状态：已通过用户审核
部署目标：用户自有域名与腾讯云 Linux 服务器  
交付形态：Docker Compose

## 1. 产品目标

建设一个供用户和家人使用的公司投资信息网站。网站默认通过 iFinD 官方 HTTP 接口后台查询数据，并在取得合法授权时接入公司、交易所、监管机构和资讯提供方的原始资讯，帮助非专业用户快速了解关注公司的价格、估值、业务构成、财务状态、经营异常和近期信息变化；只有在用户明确点击“生成深度研究”后，才调用 OpenAI 兼容的大模型接口生成投资逻辑、风险、催化剂和证伪条件。

第一版的核心目标：

1. 用家庭关注清单和公司搜索快速进入公司数据。
2. 严格区分来源事实、确定性计算和 AI 观点。
3. 用缓存、批量查询和限速保护 iFinD 与模型额度。
4. 不在网页代码、数据库、Docker 镜像或日志中保存密钥。
5. 支持桌面和手机阅读。
6. 通过 Docker Compose 在腾讯云服务器上稳定运行。
7. 让用户清楚知道每类数据的来源、更新时间、刷新规则和完整性。

## 2. 第一版非目标

第一版不包含：

- 券商交易、下单或自动交易。
- 持仓数量、买入成本和盈亏管理。
- 多租户、家庭成员独立账号或权限体系。
- 公网开放的原始 iFinD 数据下载服务。
- 秒级逐笔行情。
- 自动在没有人工介入的情况下绕过 iFinD 登录、验证码或风控。
- 未经授权地批量抓取、转载或向家庭范围以外分发新闻与社交媒体内容。
- 将 AI 观点冒充 iFinD 原始数据。

## 3. 已确认的产品决策

- 首页采用“家庭关注清单＋公司搜索”。
- 第一版暂不使用家庭口令登录。
- 默认页面仅显示原始来源数据和确定性计算结果。
- 公司财务数据、业务构成和确定性经营异常提示在默认页面展示。
- 公司相关资讯与舆情采用可插拔数据源；默认页展示原始资讯与确定性统计，AI 影响解释只进入深度研究页。
- “生成深度研究”后形成独立的深度研究页面。
- 深度研究通过 OpenAI 兼容接口调用，可切换 OpenAI、DeepSeek、通义或其他兼容服务。
- 关注公司价格在交易时段每 10 分钟批量刷新。
- 单家公司允许手动刷新价格；同一公司冷却 2 分钟，全站每日最多 100 次手动刷新。
- 图表使用混合模式：默认趋势线与估值区间，可切换前复权 K 线。
- 部署使用 Docker Compose，入口使用 Nginx，证书使用 Certbot 管理。
- 应用采用 Next.js 模块化单体，数据存储使用 PostgreSQL。
- iFinD `refresh_token` 存放于腾讯云密钥管理服务；由管理员按照产品说明书手动更新，不建设自动轮换工具。
- 原 Codex iFinD 技能继续只从 macOS 钥匙串读取密钥。

## 4. 信息分类与页面边界

### 4.1 三层信息

#### A. 原始来源数据

由来源直接返回或披露、未经网站观点加工的数据，例如：

- 最新价格、涨跌幅、开盘、最高、最低、成交量、行情时间。
- 历史开高低收和成交量。
- 标准化估值字段。
- 标准财务报表指标。
- 产品、业务、地区或渠道等业务构成数据。
- 公告日期、标题、类型、序号和 PDF 地址。
- 宏观经济指标。
- 交易日期。
- 公司、交易所、监管机构和取得授权的资讯提供方返回的新闻标题、来源、发布时间和原文地址。

页面先显示数据类型标签 `原始来源数据`，再显示来源徽标：

- `iFinD接口`
- `公司/交易所/监管机构`
- `外部资讯`

来源徽标不能被合并成统一的“官方数据”。每条原始记录必须保留来源、原始标识、来源时间、本站获取时间、完整性和授权范围。

#### B. 确定性计算

仅使用公开公式、固定规则或经过配置的阈值处理原始来源数据，例如：

- 三年最高价、最低价和当前区间位置。
- 距历史高低点的涨跌幅。
- 收入、利润和现金流同比变化。
- 历史估值区间和当前百分位。
- 自由现金流等统一公式指标。
- 财务与业务构成的经营异常提示。
- 资讯数量趋势、来源构成和主题数量，不包含投资影响判断。
- 数据新鲜度、完整性和返回耗时。

页面标签：`确定性计算`

所有计算项必须提供公式或规则、输入字段、报告期、币种、单位和阈值版本。公司披露的非 GAAP 自由现金流不能与“经营现金流减资本开支”的网站计算值混为一谈。

#### C. AI 生成数据

只有生成深度研究后才存在，例如：

- 核心投资观点。
- 多头逻辑和反方观点。
- 公告事件摘要与影响解释。
- 资讯与舆情摘要及业务影响解释。
- 宏观敏感因素与敏感程度。
- 风险、催化剂和证伪条件。
- 情景价格区间。
- 证据置信度和待核实事项。

页面标签：`AI生成`

AI 内容不得出现在默认公司数据页。

### 4.2 公告正文

iFinD 公告接口返回公告元数据和 PDF 地址。默认数据页只显示公告清单，不解释事件影响。生成深度研究时，系统可以下载选定范围内的 PDF、提取正文和表格，再交给模型分析。

公告正文属于深度研究输入，不属于接口结构化数据。页面引用公告时必须保留公告标题、日期、证券代码和原始 PDF 地址。

第一版生成综合深度研究时，默认选择：

- 最新年度报告。
- 最新中期或季度业绩公告。
- 最近 12 个月内的回购、融资、并购、分拆、重大投资、监管和重大业务更新。
- 去重后最多 20 份 PDF。

超过上限时优先保留更新、更重大且与核心财务或业务变化直接相关的公告，并在研究页列出未纳入分析的公告数量。公告数据不完整时，深度研究必须显式标记来源限制。

### 4.3 公司资讯与舆情

资讯与舆情模块采用可插拔数据源。第一版按以下顺序接入：

1. 在 iFinD SuperCommand 中验证当前账户是否具有新闻、研报摘要或舆情相关的数据池、指标和权限。
2. 公司官网、交易所和监管机构提供的公开原始信息。
3. 取得授权的主流资讯提供方。
4. 社区和社交媒体只作为以后可选来源，必须单独标记，且不得与官方来源混排。

iFinD 公开 HTTP 文档未给出独立、稳定的新闻舆情路由，因此在指标和权限验证完成前，不把新闻接口写死为生产依赖。若没有合适的授权数据源，页面显示“资讯源未配置”，不使用通用网页搜索或未经授权的抓取作为静默替代。

默认公司数据页只显示：

- 标题、来源、发布时间、原文地址和匹配到的公司或业务关键词。
- 官方来源、主流资讯、其他来源的明确分级。
- 一段时间内的资讯数量、来源多样性和基于预设关键词映射的主题数量。
- 数据覆盖范围、最后更新时间和完整性。

默认页不显示单一“舆情分数”，也不显示正面、中性、负面等情感判断。资讯内容只有在生成深度研究时才由 AI 解释其业务和投资影响。

生成深度研究时，资讯默认选择最近 90 天内与公司直接相关的公司、交易所、监管机构和主流授权来源，去重后最多 50 条；优先保留更新、更可信且与收入、成本、监管、资本配置或核心产品直接相关的资讯。超出上限、正文不可用或授权不允许分析时，研究页必须列出未纳入数量和原因。

## 5. 页面设计

### 5.1 首页：家庭关注清单

首页包含：

- 产品名称和整体数据状态。
- 公司名称或代码搜索。
- 关注公司卡片。
- 当前价格、涨跌幅和行情时间。
- 三年价格区间位置。
- 关键原始数据变化。
- 最近新增公告数量，但不显示 AI 事件判断。
- 最近新增资讯数量和来源状态，但不显示 AI 舆情判断。
- 关注公司添加、移除和排序。
- 下一次自动更新时间。

首页卡片不显示“观察偏多”“值得买入”等 AI 判断。未生成深度研究时，只显示数据状态；已经生成研究时，可以显示“存在深度研究”入口，但不直接复制 AI 观点到首页。

### 5.2 公司数据页

公司数据页是一页纵向数据档案，包含：

1. 公司名称、证券代码、市场和行业。
2. 当前价格、涨跌幅、行情时间、下次更新时间和手动刷新按钮。
3. 数据来源图例。
4. 行情与估值。
5. 完整财务数据与业务构成。
6. 确定性经营异常提示。
7. 公告清单。
8. 公司资讯与舆情原始清单。
9. 由确定性市场／行业映射关联的宏观原始序列入口。
10. “生成深度研究”按钮。

公司数据页不得展示 AI 投资观点。

公司数据页关联的宏观序列只能来自预先配置的确定性映射，例如港股对应港元利率和恒生指数、消费行业对应社会消费品零售总额。页面只展示原始序列和变化，不判断敏感度，也不解释其对公司的投资影响；公司特有的宏观敏感因素只出现在深度研究页。

#### 行情与估值

- 默认展示三年价格趋势。
- 支持 1 年、3 年和可扩展周期。
- 支持趋势线与 K 线切换。
- K 线默认使用前复权日线，并支持周线和月线。
- 显示三年最高、最低、当前价格和回撤。
- 估值温度尺表示当前估值在历史区间的位置，不使用“低估／高估”的投资结论性措辞；使用“区间低位／中部／区间高位”。
- 估值字段不可用时显示缺失原因，不用价格区间替代估值区间。

#### 财务数据

财务模块必须支持：

- 年度和季度切换。
- 利润表、资产负债表、现金流量表切换。
- 最近三年或最近八个季度对比。
- 原始金额、同比变化和统一单位。
- 币种与报告期。
- 指标来源和更新时间。

第一版重点指标：

- 营业收入。
- 毛利或毛利率，若接口口径可用。
- 经营利润。
- 归母净利润。
- 每股收益。
- 现金及等价物。
- 有息负债。
- 经营现金流。
- 资本开支。
- 网站统一公式计算的自由现金流。
- ROE、ROIC、净利率和资产负债率，前提是对应 iFinD 指标已验证。

不同市场使用经过验证的指标配置。未在 iFinD 指标查询工具中确认的指标 ID 不得进入生产配置。

#### 业务构成

业务构成模块在接口和权限允许时，支持按产品、业务分部、地区和渠道展示：

- 收入。
- 收入占比。
- 收入同比变化。
- 成本、毛利和毛利率。
- 报告期、币种、单位和来源。

优先使用 iFinD 结构化指标或经过验证的专题报表。不同市场或公司只披露部分维度时，保留实际披露结构，不强行映射成统一分类。接口缺少结构化分部数据时，默认页显示缺失原因；从年报或业绩公告提取的数据必须标记为 `公告提取`，并保留公告页码和原始链接，不能冒充 iFinD 结构化字段。

#### 确定性经营异常提示

默认公司数据页使用公式和行业配置阈值检测异常，不调用 AI。第一版至少支持：

- 收入增长而利润下降，或利润增长显著偏离收入增长。
- 毛利率、经营利润率或净利率显著变化。
- 应收账款或存货增速持续高于收入增速。
- 经营现金流持续低于净利润，或经营现金流与净利润方向背离。
- 自由现金流转负、资本开支异常增加。
- 有息负债和利息费用快速增加。
- 投资收益、资产处置或其他非经营项目对净利润贡献过高。
- 减值损失明显增加，前提是接口字段已经验证。

每条提示必须显示触发指标、公式、当前值、比较期、阈值、行业规则版本和数据完整性，并明确写明“数据异常不等于利好、利空或财务造假”。银行、保险、制造、消费和互联网等行业使用不同规则；没有经过验证的行业规则时只展示基础比率，不触发异常结论。

#### 公告清单

默认显示：

- 日期。
- 发布时间。
- 证券代码与简称。
- 公告标题。
- 公告类型。
- PDF 地址。
- 查询完整性。

不在数据页显示“利好、利空、事件驱动”等模型判断。

#### 资讯与舆情清单

默认显示：

- 发布时间。
- 来源名称和来源等级。
- 标题和原文地址。
- 匹配到的公司、人物或业务关键词。
- 查询覆盖范围和完整性。

默认页不解释资讯对收入、估值或股价的影响。来源正文不可用时只保存和展示授权范围内的元数据，不绕过付费墙或访问限制。

### 5.3 深度研究页

深度研究页在用户点击生成后创建，并绑定一个不可变的数据快照。

包含：

- 公司、证券代码和生成时间。
- 数据快照时间和引用的数据条数。
- 分析过的公告清单。
- 分析过的资讯清单和来源等级。
- 核心观点。
- 多头逻辑。
- 反方观点和主要风险。
- 公告事件解释。
- 经营异常原因、暂时性或结构性判断及后续验证指标。
- 资讯与舆情对业务的可能影响。
- 宏观敏感因素。
- 催化剂。
- 证伪条件。
- 情景分析。
- 待核实事项。
- 证据置信度。

页面所有观点明确标记为 `AI生成`。点击引用数字可返回公司数据页查看接口字段、计算公式和时间。

重新生成会创建新版本，不覆盖历史研究。数据快照未发生实质变化时，系统提示复用最近研究，用户仍可明确选择重新生成。

## 6. 视觉方向

产品定位为“安静的家庭研究桌面”，不模拟交易终端。

颜色：

- 墨蓝 `#162232`：主文字和深度研究主视觉。
- 瓷灰 `#F3F6F7`：页面背景。
- 青绿 `#0B7A6E`：数据改善和正常状态。
- 金色 `#B7862E`：等待验证和提醒。
- 砖红 `#B14949`：明确风险与负向变化。
- 钴蓝 `#3758B2`：接口数据、链接和图表主线。

字体：

- 中文标题使用宋体风格系统字体。
- 正文使用苹方、微软雅黑等系统无衬线字体。
- 数字使用 DIN Alternate 或等宽字体回退。

视觉签名：

- “估值温度尺”贯穿首页和公司数据页。
- 温度尺表示历史区间位置，不直接给出买卖建议。
- 红绿颜色不主导整页。

交互：

- 桌面端使用章节导航。
- 手机端使用单列阅读。
- 支持键盘焦点、触摸操作和减少动画偏好。
- 价格更新只使用轻微数字过渡，不使用闪烁。
- 行情、财务、公告、资讯和宏观模块分别显示自己的来源时间、本站获取时间和刷新周期。

## 7. 系统架构

采用单体全栈应用：

```text
浏览器
  ↓ HTTPS
Nginx
  ↓
Next.js 模块化单体
  ├─ React 页面与后端 API
  ├─ iFinD 适配器
  ├─ 资讯源适配器
  ├─ 指标归一化与计算
  ├─ 经营异常规则引擎
  ├─ 缓存与额度控制
  └─ OpenAI 兼容模型编排
  ↓
PostgreSQL

外部依赖
  ├─ iFinD HTTP API
  ├─ 公司/交易所/监管机构与授权资讯源
  ├─ OpenAI 兼容模型 API
  └─ 腾讯云密钥管理服务
```

Docker Compose 包含：

- `nginx`：域名入口、HTTPS 终止、反向代理、基础单 IP 限流、安全响应头、请求大小限制和静态资源缓存。
- `certbot`：证书首次申请和定时续期；证书通过只读卷提供给 Nginx。
- `app`：前端、后台 API、iFinD 和模型逻辑。
- `postgres`：业务数据、缓存元数据、额度统计和研究版本。
- 持久化数据卷：PostgreSQL 数据、证书和必要迁移状态。

第一版不引入 Redis、消息队列或独立微服务。应用仅运行一个负责定时调度的实例，避免重复刷新。PostgreSQL 从第一版开始使用，以支持并发访问、历史快照和以后增加用户；业务模块保持边界清晰，避免在扩展前过早拆分微服务。

Nginx 提供网络入口层的基础限流。业务级限速、手动刷新冷却、每日调用上限和证券代码允许列表仍由应用与 PostgreSQL 强制执行。

### 7.1 技术栈

- 前端与服务端：Next.js、React、TypeScript。
- 图表：Apache ECharts，用于趋势线、估值区间、业务构成和 K 线。
- 输入与模型输出校验：Zod。
- 数据访问与迁移：Drizzle ORM。
- 数据库：PostgreSQL。
- HTTP 调用：服务端标准 `fetch`；所有第三方适配器使用统一的超时、重试和脱敏错误模型。
- 模型调用：OpenAI 兼容协议，在服务端配置 Base URL、模型和密钥。
- PDF 处理：独立模块提取正文和表格，并保留公告页码映射。
- 日志：结构化日志，集中配置敏感字段脱敏。
- 自动测试：Vitest；浏览器流程与响应式页面使用 Playwright。

模块化单体至少划分为证券主数据、行情、财务、业务构成、经营异常、公告、资讯、宏观、深度研究、额度控制和密钥读取。模块之间通过明确的服务接口和数据结构通信，页面不得直接调用第三方数据源。

### 7.2 扩展路线

1. 第一阶段使用 Nginx、单个应用实例和 PostgreSQL。
2. 需要多个应用实例时引入 Redis，统一分布式缓存、冷却时间、限流和任务锁。
3. PDF、AI 和定时刷新任务增加时，引入持久化任务队列和独立 Worker。
4. 访问量继续增加时，在 Nginx 前增加腾讯云 CLB/CDN，并运行多个无状态应用实例。
5. 公告 PDF 和可授权保存的资讯正文转移到腾讯云 COS；PostgreSQL 只保存元数据和对象引用。
6. 增加账号后，关注清单、研究历史、额度和权限改为用户级数据。

Nginx、应用、数据库和任务执行层保持可独立替换，扩展时不改变页面的数据来源分类和研究快照模型。

## 8. iFinD 数据路由

| 能力 | iFinD 路由 |
|---|---|
| 最新行情 | `realtime` |
| 历史价格和 K 线 | `history` |
| 分钟行情（以后扩展） | `high-frequency` |
| 公司和财务指标 | `company` |
| 公司指标时间序列 | `series` |
| 专题报表 | `data-pool` |
| 公告清单 | `announcements` |
| 宏观经济 | `macro` |
| 交易日 | `trade-dates` |
| 新闻、研报摘要或舆情 | 优先验证 `data-pool` 或账户可用报告；公开文档没有固定独立路由 |

完整指标字典不在公开 HTTP 文档中。实施阶段必须在 iFinD SuperCommand 指标查询工具中验证 A 股、港股和美股所需指标 ID、参数、单位和权限。

收入、成本、毛利和毛利率的总量指标优先使用 `company` 或 `series`；产品、业务分部、地区和渠道等细分数据优先验证 `data-pool` 中的主营构成或分部报表。指标不可用时不从其他口径推算或猜测。

证券名称搜索使用本地缓存的证券身份主数据，不在每次键入时调用 iFinD。每个上市身份使用稳定、只读的分离模型，至少保存 `companyId`、`listingId`、`issuerLegalName`、`nameZh`、`exchange`、`exchangeCode`、`displayCode`、`formatAliases`、`vendorCodes` 和 `configured`。其中：

- `displayCode` 是站内 canonical 展示与运行代码；阿里巴巴使用 `9988.HK`。
- `formatAliases` 只表示同一交易所代码的格式变体；阿里巴巴的格式别名仅为 `09988.HK`。
- 百度是独立发行人与上市身份，canonical 展示代码为 `9888.HK`，格式别名仅为 `09888.HK`，当前 `configured=false`。
- `vendorCodes` 与展示代码分离。iFinD、ISIN 等供应商代码未经验证时必须保存为 `code: null, status: unverified`，不得从展示代码猜测或标记为已验证。

解析层允许 `displayCode`、`exchangeCode` 和 `formatAliases` 定位同一上市身份。搜索层还允许中文名和发行人法定名称匹配。已知但 `configured=false` 的身份保留在搜索结果中并明确显示“未收录”，但不得加载公司数据。

普通未知代码和已知但未收录身份统一返回 `SECURITY_NOT_CONFIGURED`。已知身份的错误可附带请求代码、canonical `displayCode` 与真实发行人名称；未知合法或非法代码不得伪造发行人。只有输入记录中的发行人名称可映射到一个公司、而证券代码明确属于另一个公司时，数据校验层才返回 `SECURITY_IDENTITY_CONFLICT`。历史 Mock 错链提示属于纠错说明，不能输出为身份冲突错误。

初始证券身份主数据通过经过验证的数据池或管理员导入获得；找不到可靠映射时要求用户输入准确证券代码，不猜测市场。

## 9. 行情刷新与额度保护

### 9.1 自动刷新

- 仅在对应市场交易时段刷新。
- 关注公司按市场批量查询。
- 刷新周期为 10 分钟。
- 所有浏览器共享同一缓存。
- 休市后停止轮询，并保留最后收盘行情。
- 搜索非关注公司时按需查询一次，缓存 10 分钟。

### 9.2 手动刷新

- 公司数据页提供“立即刷新”。
- 只查询目标公司的必要行情字段。
- 同一公司刷新后冷却 2 分钟。
- 全站每天最多 100 次手动刷新。
- 达到上限后继续显示自动刷新时间。

### 9.3 其他缓存

建议初始有效期：

- 历史行情：每日更新。
- 财务数据：每日检查；财报发布后失效。
- 公告清单：交易日每数小时检查，只查询新增日期范围。
- 资讯清单：根据数据源授权和更新频率配置，第一版建议每 30 至 60 分钟增量检查。
- 宏观数据：每日或按发布日期更新。
- 深度研究：绑定数据快照，快照未变化时可复用。

系统保存每次 iFinD 请求的路由、代码、指标、时间、耗时、请求数、`dataVol`、完整性和安全错误分类，不保存请求头或令牌。

HTTP 接口没有公开的官方剩余额度端点。网站显示“本站统计使用量”；仅当官方 SDK 的 `THS_DataStatistics` 可用时才显示“iFinD 官方统计”。

### 9.4 前端更新时间说明

首页和公司数据页顶部显示统一的行情更新时间条，至少包括：

- 行情来源时间。
- 市场状态：交易中、午休、已收市或休市。
- “交易时段每 10 分钟自动更新”。
- 下一次预计更新时间。
- “立即刷新”按钮。
- 手动刷新后的剩余冷却时间。
- 当前数据来自新请求还是缓存。

示例：

> 行情时间 11:38｜交易中｜每 10 分钟自动更新｜下次更新 11:48｜立即刷新

手动刷新后：

> 已更新｜1 分 42 秒后可再次手动刷新

失败或休市时：

> 本次更新失败，继续显示 11:38 的缓存数据
> 已收市，当前为最后收盘数据

行情的“立即刷新”只刷新目标公司的必要价格字段，不刷新财务、业务构成、公告、资讯和宏观模块。每个非行情模块在自己的标题处分别显示来源时间、本站获取时间、刷新周期和完整性，避免用户误以为整页数据每 10 分钟更新。

## 10. AI 深度研究

模型接口使用 OpenAI 兼容协议，配置项包括：

- Base URL。
- 模型名称。
- API 密钥。
- 超时和最大输出长度。
- 每日调用预算。

第一版默认全站每天最多成功生成 10 份深度研究；该值可在服务器配置中调整。相同公司和相同数据快照默认复用已有结果，只有用户明确选择“重新生成”时才再次调用模型。

调用流程：

1. 冻结公司数据快照。
2. 选择并下载需要分析的公告 PDF 和授权范围内的资讯正文。
3. 提取公告正文、表格和页码映射，并加入确定性经营异常记录。
4. 明确把公告和资讯正文当作不可信数据，防止提示注入。
5. 构造带来源引用、来源等级和完整性状态的结构化输入。
6. 调用模型。
7. 用结构化模式校验返回内容。
8. 校验引用数字是否存在于输入快照，引用资讯是否存在于来源清单。
9. 保存研究版本和来源关系。

模型失败时不得影响公司数据页。格式修复最多自动重试一次。

## 11. 数据存储

PostgreSQL 保存：

- `companies`：公司与代码映射。
- `watchlist`：家庭关注清单和排序。
- `market_snapshots`：行情快照。
- `financial_snapshots`：财务数据快照。
- `business_breakdown_snapshots`：产品、业务分部、地区和渠道等构成数据。
- `anomaly_events`：确定性经营异常、公式、阈值和规则版本。
- `announcement_records`：公告元数据。
- `news_records`：授权范围内的资讯元数据、来源等级和对象引用。
- `macro_snapshots`：宏观数据。
- `research_snapshots`：生成研究时使用的不可变数据快照。
- `research_reports`：AI 研究版本。
- `usage_events`：iFinD 和模型使用统计。
- `system_events`：安全的状态和错误记录。

PostgreSQL 不保存：

- iFinD `refresh_token`。
- iFinD `access_token`。
- 模型 API 密钥。
- 腾讯云长期访问密钥。

建议每日加密备份数据库到腾讯云 COS，并保留可配置的滚动版本。

## 12. 密钥管理与手动更新

### 12.1 腾讯云

- iFinD `refresh_token` 和模型 API 密钥存放于腾讯云密钥管理服务。
- CVM 使用腾讯云实例角色访问指定密钥，不写入长期腾讯云访问密钥。
- 应用只在内存中使用密钥。
- 密钥不得进入浏览器、PostgreSQL、镜像、日志或错误详情。

### 12.2 iFinD `access_token`

- 应用用 `refresh_token` 换取 `access_token`。
- `access_token` 只保存在内存。
- 到期或收到鉴权错误时自动刷新并安全重试一次。

### 12.3 产品说明书中的手动更新流程

第一版不建设自动轮换工具，也不自动从 iFinD 登录页面读取 `refresh_token`。产品说明书必须提供以下管理员流程：

1. 管理员亲自登录 iFinD 官方账号详情页，完成可能出现的验证码，并取得新的 `refresh_token`。
2. 在腾讯云密钥管理服务控制台为现有 iFinD 密钥创建新版本；不把令牌写入 `.env`、终端命令、脚本参数或普通文本文件。
3. 通知应用重新加载密钥；第一版可通过重启 `app` 容器完成，但不得重建数据库或清空缓存。
4. 检查应用健康状态，确认新的密钥版本已加载且日志中没有令牌。
5. 执行一次最小行情查询，确认鉴权、额度记录和返回时间正常。
6. 若 Codex iFinD 技能也需要使用同一令牌，单独更新 macOS 钥匙串项目 `codex.ifind.quantapi`，账户名称保持 `refresh_token`。
7. 清理剪贴板，并退出包含令牌的 iFinD 页面。

产品说明书同时提供更新失败的回退步骤：腾讯云密钥仍保留上一版本；若新版本验证失败，管理员恢复上一版本并重新加载应用。产品不保存 iFinD 账号密码，不自动绕过验证码。

网站每天检查令牌声明或接口返回的可用期限，在剩余 7 天、3 天和 1 天时显示提醒。实际有效期以令牌和接口行为为准，不假设官方文档中的长期有效描述。

## 13. 无登录状态下的安全边界

虽然第一版不使用家庭口令，仍必须：

- 禁止搜索引擎收录。
- Nginx 限制单 IP 基础请求频率，应用再次执行公司级、用户动作级和每日总量限制。
- 限制手动刷新和 AI 调用。
- 设置 AI 每日总预算。
- 不暴露原始 iFinD 转发接口。
- 不暴露原始资讯转发接口，也不向未授权用户提供资讯正文下载。
- 不允许网页修改密钥、模型地址或系统配置。
- 限制请求体大小和公司搜索输入。
- 对所有证券代码、路由和指标使用允许列表。
- 不在客户端返回第三方错误原文中的敏感信息。

无登录不能等同于真正的访问控制。系统结构必须允许以后增加家庭口令而不重写数据层。

上线前需要用户确认当前 iFinD 授权是否允许向家庭成员展示接口数据。网站定位为小范围私人研究工具，不作为公开数据服务。

## 14. 错误与降级

- 行情失败：显示最近成功行情和时间。
- 指标无权限：显示字段不可用和安全错误分类。
- 财务指标缺失：保留缺失，不转换为零。
- 业务构成缺失：显示接口、披露或权限原因，不用总收入推断分部收入。
- 经营异常数据不完整：显示未执行相应规则，不基于部分字段触发结论。
- 公告额度不足：显示缓存公告、最后成功时间和不完整状态。
- 资讯源不可用或未配置：显示来源状态，默认页和深度研究都不得伪造资讯。
- 宏观接口失败：隐藏相关原始数据，不生成伪造值。
- 模型失败：公司数据页继续可用，研究生成记录失败原因。
- 令牌即将到期：显示提醒。
- 令牌失效：停止新请求，避免连续重试。
- 数据来源冲突：同时保留两个口径并说明，不自动选择有利于某一观点的数字。

## 15. 部署、更新和备份

- Nginx 负责 HTTPS 入口、反向代理、基础限流和静态资源缓存。
- Certbot 负责证书首次申请和定时续期；续期成功后安全重载 Nginx。
- 应用通过健康检查后才切换流量。
- 更新前备份 PostgreSQL。
- 新版本失败时恢复旧镜像和数据库备份。
- 运行日志只包含安全元数据。
- 数据库每日备份到 COS。
- Docker 镜像不包含 `.env`、令牌或模型密钥。

域名、腾讯云地域、COS 存储桶和密钥名称作为部署参数提供，不写死在源码中。

## 16. 测试与验收标准

### 数据

- 真实 iFinD 行情可查询并显示来源时间。
- 10 分钟自动刷新只由服务器执行一次，不随浏览器数量倍增。
- 手动刷新遵守 2 分钟冷却和每日 100 次上限。
- 三年高低点与回撤计算有自动测试。
- 财务表保持币种、单位、报告期和缺失值。
- 业务构成保持原始披露维度，接口数据和公告提取数据不会混淆。
- 每条经营异常提示的公式、阈值、行业规则和缺失数据行为有自动测试。
- 所有生产指标 ID 均来自经过验证的配置。
- 公告分页、去重、缓存和额度失败行为经过测试。
- 资讯来源等级、去重、授权范围、缓存和不可用状态经过测试。

### 页面

- 首页不显示 AI 投资观点。
- 公司数据页只出现 `原始来源数据`、具体来源徽标与 `确定性计算`，不出现 AI 投资观点。
- 深度研究页所有观点标记为 `AI生成`。
- 数据页与研究页互相引用，但不覆盖彼此内容。
- 行情更新时间条显示市场状态、来源时间、下次刷新、缓存状态和手动刷新冷却。
- 财务、公告、资讯和宏观模块分别显示自己的刷新时间和周期。
- 桌面与手机均可使用。
- 键盘焦点可见，颜色不作为唯一状态提示。

### 安全

- 浏览器响应、日志、数据库和镜像中不存在任何令牌或 API 密钥。
- 非允许列表的路由和指标无法调用。
- 公告和资讯正文中的提示指令不能改变系统分析要求。
- Nginx 基础限流和应用业务限流分别经过测试。
- 手动更新 Token 的验证和回退过程不会把密钥写入响应、日志、数据库或镜像。

### AI

- 深度研究绑定明确的数据快照。
- 相同数据快照可复用研究。
- 重新生成创建新版本。
- 数字引用必须能回到数据页。
- 模型超时或结构错误不影响默认数据页。

## 17. 实施补充（已采纳用户批注）

### 17.1 资讯与舆情边界
- 默认公司数据页与首页仅展示可核验来源事实：标题、来源、发布时间、抓取时间、原始链接、去重状态与授权范围。
- 情绪、影响、争议、可信度只在深度研究页由模型生成。
- 资讯模块必须保留来源层级（官方/主流/其他）与免责声明（“非授权正文不展示影响判断”）。

### 17.2 财务与细分口径
- 财务与业务构成仅展示在 iFinD 已验证的指标口径、专题报表或公告披露字段中。
- 对新增分部数据保留源字段名、币种、单位、报告期与口径来源；不得跨口径拼接总量。
- 缺口径时显示“未配置/暂不支持”，不得以 0 或估算替代。

### 17.3 经营异常确定性信号
- 默认页必须逐项列出：规则名称、阈值、输入值、触发状态、缺失原因。
- 深度研究页再给出原因解释与投资含义，不得把未触发项展示为“结论”。

### 17.4 刷新透明度
- 公司页与首页均需显示：行情时间、缓存状态、下次自动刷新、是否交易时段、手动刷新剩余冷却、今日手动刷新已用/上限。
- 任何接口失败必须回退到最近成功数据并显式提示“使用缓存”。

### 17.5 令牌与安全边界
- 删除自动轮换与自动更新动作；仅保留管理员手工从 iFinD 登录页获取 refresh_token 的说明。
- 明确要求：不落盘、不进页面、数据库、日志、仓库、容器镜像。

### 17.6 反向代理与运行时
- 统一使用 Nginx，职责包括 HTTPS、反向代理、静态资源缓存、请求体大小限制、安全响应头、基础限速。

### 17.7 技术栈约束与扩展路线（落地实现建议）
- 优先实施为单体全栈 TypeScript（例如 Next.js）+ SQLite 起步，通过数据访问层隔离。
- 后续可平滑迁移至 PostgreSQL（通过 schema + repository layer）。
- 调度仍为单实例，后续高并发时再拆 worker/队列/Redis。
- 预留家庭登录、RBAC、审计、水平扩容接口，不把它们提前固化为假设前提。
