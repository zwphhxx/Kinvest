# iFinD HK Alibaba fixed template probe proposal

Date: 2026-09-01. Proposal ID: `HK_ALIBABA_9988_V1`.

This is a non-secret, non-executable proposal for collecting the minimum
evidence needed by `HK_EQUITY_V2`. It does not authorize a real request,
change the existing R1 manifest or expose real data to the family page.

## Fixed budget and execution boundary

| Item | Fixed limit |
| --- | --- |
| Authentication | At most 1 request using the existing tmpfs refresh token boundary |
| Business requests | Exactly the approved subset, at most 3 total |
| Retries | 0, including format repair and authentication retry |
| Concurrency | 1 |
| Persistence | Normalized safe summary only; no raw response or RequestId |
| Promotion | Never automatic; all observations remain unverified |

The proposal is `executionStatus=blocked` with reason
`IFIND_PROBE_REQUIRES_EXPLICIT_APPROVAL`. A later implementation PR must add
an administrator-only execution entry, reuse the shared quota and require a
new approval at the moment of the real call.

## Exact candidate requests

### 1. Identity observation

```json
{
  "codes": "9988.HK",
  "indipara": [
    { "indicator": "ths_stock_short_name_stock" }
  ]
}
```

Endpoint: `POST /api/v1/basic_data_service`.

The [official manual](https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/help-center/manual.html)
shows this indicator in an A-share example. It does not state that the
indicator applies to HK equities. Therefore this request is a candidate
compatibility probe, not verified identity metadata. A successful name/code
response still requires issuer and listing comparison before any promotion.

### 2. Quote observation

```json
{
  "codes": "9988.HK",
  "indicators": "latest,preClose,open,high,low,amount,volume,tradeDate,tradeTime"
}
```

Endpoint: `POST /api/v1/real_time_quotation`.

The fields came from the recorded official SuperCommand observation. The
manual documents the HTTP shape, but neither source proves the current
account entitlement, actual response shape, currency, units, timezone or
trading status. Missing fields stay missing.

### 3. Financial observation

```json
{
  "codes": "9988.HK",
  "indipara": [
    {
      "indicator": "revenue_oas",
      "indiparams": ["20260331", "1", "BB"]
    }
  ]
}
```

Endpoint: `POST /api/v1/basic_data_service`.

The selector and parameters were generated by official SuperCommand. They do
not prove the actual report period, period type, currency, unit, scale or
disclosure scope. Numerical agreement with an issuer disclosure remains
comparison-only evidence.

## Required implementation before any real run

1. Add a dedicated administrator-only service and HTTP action that accepts no
   arbitrary code, indicator, parameter or request body.
2. Reserve the shared iFinD quota before reading the secret and enforce one
   active run, zero retry and the fixed request order.
3. Strictly parse only allowlisted response fields and clear access-token
   buffers on every path.
4. Persist only normalized observations, safe failure classes, counts and
   timestamps. Never persist raw provider payloads, credentials or RequestId.
5. Keep all seven verification dimensions unverified until a separate review
   proves each dimension from provider and issuer evidence.
6. Obtain explicit approval for the exact live invocation after the code PR,
   production deployment and administrator login are complete.

Until then, the existing market service must continue rejecting Alibaba with
`IFIND_MARKET_CASE_UNVERIFIED` before secret access or quota consumption.
