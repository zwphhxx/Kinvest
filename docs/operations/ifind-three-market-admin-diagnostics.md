# iFinD 三市场管理员诊断运行手册

本文定义 Kinvest R1 三市场诊断的非秘密运行边界。该能力仅供管理员诊断，家庭看板继续使用 Mock 数据且行为不变。本文不授权真实调用，不包含账户标识、凭据、供应商原始响应，也不执行生产操作。

## 1. 固定案例与查询边界

R1 只允许以下三个固定案例，顺序不可由网页或调用方改变：

| 案例 ID | 市场 | 发行人 | 展示代码 | 用途 |
|---|---|---|---|---|
| `HK_ALIBABA_9988` | 港股 | Alibaba | `9988.HK` | 固定港股行情与财务诊断 |
| `US_APPLE_AAPL` | 美股 | Apple | `AAPL.US` | 固定美股行情与财务诊断 |
| `CN_MOUTAI_600519` | A 股 | Kweichow Moutai | `600519.SH` | 固定 A 股行情与财务诊断 |

系统不提供任意查询，不接受调用方提交证券代码、iFinD 路径、指标 ID、日期、币种、单位或报告期。管理员必须逐张案例卡片运行；不提供批量运行，不提供 run-all，也不得用脚本把三个案例合并成一次授权。

## 2. 证据前置条件与两道发布审批门

认证指标证据与 manifest 验证是每个真实案例的前置条件，不代替镜像上线审批或逐次真实调用审批。管理员必须在 iFinD 认证指标查询工具中确认供应商代码、行情字段、财务指标 ID、元数据指标 ID、单位和报告期参数，并将非秘密证据纳入审查。证据不全的案例保持不可执行，但不阻止以失败关闭状态交付和验收镜像。

1. **镜像上线审批门**：用户单独批准精确镜像及部署变更，并亲自批准 Production deployment；合并 PR 或完成指标验证都不代表已批准上线。上线与验收期间不得向 iFinD 发送真实请求，包括基础双级诊断和三市场诊断。只验证生产健康、登录保护、管理员 UI、家庭 Mock 与联合部署状态。
2. **逐案例真实调用审批门**：只有完成生产健康与 UI 验收、且对应案例满足证据前置条件后，才允许用户单独批准的真实调用。一次批准只覆盖一个市场中的一个固定案例，不得复用到其他案例或后续调用；禁止自动、批量或 run-all 调用。

当前生产 manifest 的三个案例全部未验证，因此保持失败关闭（fail-closed）。fixture 中的测试 ID 不能作为生产证据，CI 通过也不能越过上述任一门。当前证据状态见 [iFinD three-market indicator evidence](ifind-three-market-indicator-evidence.md)。

## 3. 行情与财务口径

所有结果先规范化，再进入管理员诊断快照。币种、单位、报告期和来源模式都必须来自已经验证的案例 manifest 与供应商证据，不得根据证券市场、发行人名称或数值大小推断。

| 市场 | 固定案例 | 行情币种 | 财年规则 | 报告期选择 |
|---|---|---|---|---|
| 港股 | Alibaba `9988.HK` | `HKD` | 财年截止 3 月 31 日 | 最近两个年度及最新已披露中期 |
| 美股 | Apple `AAPL.US` | `USD` | 52/53 周财年，通常在 9 月末结束 | 最近两个年度及最新已披露中期 |
| A 股 | Kweichow Moutai `600519.SH` | `CNY` | 财年截止 12 月 31 日 | 最近两个年度及最新已披露中期 |

以上币种和财年规则是 Kinvest 的案例语义，不替代 iFinD 指标验证。每个财务区块还必须具备与发行人绑定的 reporting currency evidence（报告币种证据）、单位证据、报告期证据、披露日期和来源时间。验证失败时不得推断，也不得把另一个市场或发行人的证据复用过来。

- 行情时间、交易状态、币种和单位必须按 manifest 明确声明。
- 财务选择固定为最近两个年度与最新已披露中期；在已披露且时间校验通过的报告中，按报告期末选择最新期间，而不是以抓取顺序或披露先后猜测。当前 `reportDate` 表示报告期末日期；披露与来源时间参与合法性校验，不改变按期末排序的规则。
- 缺失字段保持缺失，并明确显示不可用；不得以零、上一期数值、估算值或 Mock 补齐。
- 单个数据区块只能是纯 `real` 或纯 `Mock`，real 与 Mock 不得混合。部分真实字段缺失时，整个真实区块仍保留缺失状态，不能降级拼接 Mock。

## 4. 本地配额与并发

下列限制是 Kinvest 本地安全上限，不代表 iFinD 官方剩余额度：

| 限制 | 固定值 |
|---|---:|
| 全局并发（global in-flight） | `1` |
| 单案例冷却（case cooldown） | 5 分钟 |
| 单案例每日上限（case daily） | `5` |
| 全局每日上限（global daily） | `12` |

每日边界按 `Asia/Shanghai` 自然日计算。失败、拒绝、冷却、并发占用和时钟回拨均通过稳定状态返回；页面不得把本地剩余额度描述为供应商官方额度。

## 5. 管理员 HTTP 契约

| 接口 | 访问边界 | 行为 |
|---|---|---|
| `GET /api/admin/ifind/market-cases` | 有效管理员会话 | 返回三个固定案例、配额与最近状态的正向 DTO |
| `GET /api/admin/ifind/market-cases/:caseId` | 有效管理员会话 | 返回一个固定案例最近的规范化快照 |
| `POST /api/admin/ifind/market-cases/:caseId/run` | 管理员会话、同源、CSRF、JSON 空对象 | 在证据前置条件、上线验收和本次调用批准均满足后执行一次固定案例 |

读接口和写接口都不得返回原始供应商 payload、供应商错误文本、RequestId、请求头、token 或内部异常。安全状态只使用受控值，例如 `success`、`partial`、`failed`、`busy`、`cooldown`、`daily-limit`、`unavailable`。安全错误只使用稳定 Kinvest 错误码和固定消息；未知错误归一化为通用内部错误，不透传嵌套 cause。

家庭投资接口、家庭设备 Cookie 和家庭页面不因管理员诊断而改变。家庭看板继续为 Mock 且保持不变；管理员会话不能替代家庭设备凭证读取投资数据。

## 6. 操作步骤

### 6.1 当前：只验证 fixture

合并前使用合成 fixture 完成当前离线验证：

1. 运行文档契约、案例目录、行情解析、财务解析、仓库、服务、HTTP 与前端测试。
2. 确认 fixture 使用明显的测试标识，不包含真实账户、真实响应、RequestId 或凭据。
3. 确认生产 manifest 仍是未验证并失败关闭，测试不能触发网络请求。
4. 检查管理员页面只提供三张固定案例卡片，没有任意参数输入、批量按钮或自动运行。

### 6.2 未来：先上线，不发真实请求

先提交精确镜像、联合状态、schema 兼容性和回滚边界摘要，等待用户批准部署变更及 Production deployment。安装资产、数据库迁移或服务中断仍遵守各自审批门，不因镜像上线批准而自动获得额外授权。

部署后只验收 `/api/health`、HTTPS、未授权访问拒绝、管理员页面与三张案例卡片、家庭 Mock 和部署状态。桌面及手机 UI 验收不得点击真实诊断按钮，也不得发送诊断 POST。未通过生产健康与 UI 验收时停止，不进入真实调用门。

### 6.3 未来：验收后逐次真实调用

生产健康与 UI 验收完成后，每次真实调用仍必须先完成对应案例的证据审查，然后取得每次真实调用的用户明确批准。操作员应在批准摘要中写明唯一案例 ID、市场、预期固定请求数、本地配额状态和“仅管理员诊断”。

- 一次批准仅执行一个案例。
- 不得批量、不得 run-all、不得把三个市场并行或串行打包成一次操作。
- 不得把基础连通性诊断的批准解释为行情或财务调用批准。
- 调用结束后只保存规范化结果、非秘密来源链和安全审计结果。

## 7. 回滚（rollback）与恢复验收

回滚必须取得用户明确批准；本 Task 不运行回滚命令。批准摘要应说明目标、可能中断、数据库兼容性和恢复边界，Production 审批不能代替数据库恢复的单独批准。

| 核对对象 | 必须保持或验证的约束 |
|---|---|
| 精确镜像 | 从可信发布证明和 `previous.state` 选择目标 `imageDigest`、`runtimeImageId` 与 `commit`，核对 release record 关联；不得使用浮动 tag 或仅凭本地 Image ID 推断仓库 digest |
| 联合状态 | 对照 root 持有的 `current.state`、`previous.state`，同时核对镜像身份、schema、发布来源、数据库备份位置与校验和、当前访问保护和 iFinD 模式、秘密 VersionId 与 fingerprint；不得只恢复镜像字段或直接用旧状态覆盖全部当前状态 |
| schema 兼容 | 以当前数据库的 `schemaVersion` 对照目标镜像的 `imageSchemaMin`、`imageSchemaMax`；expand 迁移也不能免除实际兼容检查，缺少范围或超出范围时失败关闭 |
| 秘密与安全状态 | 保留当前获批的秘密 VersionId、fingerprint 和访问保护配置；目标镜像必须支持当前 tmpfs provider 与安全状态，不得恢复旧镜像记录中的已撤销凭据或较弱保护模式 |

目标镜像支持当前 schema 和当前安全配置时，才可按既有部署器的兼容回滚路径恢复该精确镜像。不支持当前 schema 时返回 `ROLLBACK_REQUIRES_DB_RESTORE`，停止自动切换；数据库恢复必须另行获得用户明确批准，并使用与目标 schema 相匹配、已校验的一致性备份。数据库恢复不是本 Task 的执行内容，也不能放宽当前登录保护或真实调用审批门。

回滚不得改变、恢复或重新启用任何秘密值，不得重放旧 token、从历史 bundle 取值或录入替代材料。当前秘密缺失、VersionId/fingerprint 不一致或目标镜像不支持当前材料时停止，转入独立审批流程，不自动执行秘密恢复。

切换镜像不等于完整恢复。只有精确运行镜像与联合状态匹配、数据库 `PRAGMA quick_check` 通过、核心业务语义正常、内部健康与公网 HTTPS 正常、管理员和家庭桌面/手机 UI 正常，且未授权访问仍被拒绝、家庭数据仍为 Mock、秘密 VersionId/fingerprint 未漂移，才能记录恢复完成。恢复验收不得调用真实 iFinD；保留非秘密检查结果，不把容器启动成功当作全部验收通过。

## 8. 证据、来源链与审计

指标证据必须记录官方来源位置、查询日期、验证人、适用市场、发行人、供应商代码、指标定义、币种、单位和报告期口径。来源链（provenance）只保存支持复核的非秘密元数据，不保存认证页面内容、账户信息或完整供应商响应。

日志与审计必须脱敏：允许记录内部案例 ID、稳定结果码、请求计数、耗时和时间；禁止记录 refresh token、access token、API key、管理员密码、Cookie、请求头、供应商 payload、`errmsg`、RequestId 或异常 cause。截图不得包含控制台秘密、网络请求正文或供应商原始数据。

## 9. 本 Task 与 R1 实现 PR 的边界

本 Task 文档变更不执行生产操作（no production action），只维护文档、文档契约测试及其接线。R1 实现 PR 包含代码、测试和文档，不能将整条实现分支描述为仅文档 PR。完成或合并任一 Task 均不授权修改 Production Environment、创建或恢复秘密、部署镜像、回滚或调用真实 iFinD；家庭看板的 Mock 数据模式保持不变。
