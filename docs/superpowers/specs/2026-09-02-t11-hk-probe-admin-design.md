# Kinvest T11 港股固定模板管理员验证入口设计

## 目标

将已合并的 `HK_ALIBABA_9988_V1` 固定港股探针运行时接入一个独立的管理员页面入口，供后续在单独批准后执行一次真实样本验证。

本阶段只提供安全、可测试、默认不自动执行的诊断入口。它不开放家庭真实数据，不提升任何验证状态，不保存供应商观察值，也不接入美股或 A 股模板。

## 固定边界

- 只支持提案 `HK_ALIBABA_9988_V1`，不接受证券代码、指标或参数输入。
- 只允许已有管理员会话访问；家庭设备 Cookie 不能访问或执行。
- 页面加载、状态读取和轮询均不得调用 iFinD。
- 每次执行都需要管理员明确点击并再次确认。
- 一次执行最多包含一次认证和三次顺序业务请求，并且不重试。
- 观察结果只保存在当前应用进程内存中；重启、退出或清理后可以丢失。
- SQLite 只继续承担共享额度和租约记账，不保存观察值或供应商原始响应。
- 七项验证状态始终保持 `unverified`；本阶段不能产生 `verified`、`liveReady` 或家庭可见标记。
- 不增加 Environment Variable、Secret、数据库迁移、部署协议或 Nginx 规则。
- 开发、测试和 CI 只使用固定脱敏夹具，不执行真实 iFinD 调用。

## 方案选择

采用独立的“T11 港股模板验证”管理员卡片和独立接口，不替换现有“三市场案例诊断”。

这样可以同时保留旧诊断的历史语义，并让新探针的严格响应、额度和失败关闭规则保持清晰。未来美股和 A 股模板只有在各自证据和运行时通过后，才能以相同模式独立加入。

## HTTP 接口

新增两个固定路径：

```text
GET  /api/admin/ifind/market-probes/HK_ALIBABA_9988_V1
POST /api/admin/ifind/market-probes/HK_ALIBABA_9988_V1/run
```

`GET` 只返回本地状态，不读取秘密、不认证供应商、不消耗额度。响应包含：

```text
enabled
proposalId
proposal metadata
result
quota summary
canRun
```

`POST` 只执行固定提案。它必须满足现有管理员写操作契约：

- 有效管理员会话；
- 精确同源 `Origin`；
- 有效 CSRF token；
- `Content-Type: application/json`；
- 现有固定动作请求头；
- 请求体必须是精确空对象，不接受额外字段。

未知提案、额外路径段、查询参数、重复 JSON 键和非规范请求全部失败关闭。未启用 iFinD 管理员诊断时，接口返回稳定的不可用结果，不触碰秘密。

HTTP 层只输出严格 DTO 和稳定错误码，不输出供应商 `RequestId`、原始响应、访问令牌、refresh token、内部异常文本或数据库细节。

## 运行时接线

在现有 iFinD 管理员诊断运行时中增加可选的 `marketProbeService`。

- 仅当现有 iFinD 模式为 `admin-diagnostic`、tmpfs provider 可用且共享额度仓库初始化成功时创建服务。
- 服务复用已有的固定探针客户端、严格结果 DTO、共享市场诊断仓库和 refresh-token provider。
- 不新增第二套额度表或独立计数器。
- 运行时清理时调用该服务的 `clear()`，只清理它拥有的内存和客户端。
- 服务缺失或初始化失败时，HTTP 状态只显示不可用，应用其他管理员和家庭功能保持现有行为。

现有 `market-cases`、单指标校准和报告期诊断路径不改名、不重定向，也不委托给新服务。

## 管理员界面

在现有管理员页面增加独立的“T11 港股模板验证”卡片，视觉语言沿用当前管理员诊断区。

卡片固定展示：

- 阿里巴巴 `9988.HK`；
- 提案 ID 和模板版本；
- “家庭页面仍为 Mock”的醒目边界；
- 最近尝试时间、请求次数、业务请求次数和本地额度；
- 三个阶段的存在性或可用性观察；
- 七项验证状态，全部明确显示为“未验证”；
- 稳定失败原因和冷却状态。

按钮默认禁用，只有管理员状态、运行时状态和本地额度均允许时才启用。点击后先显示固定成本说明，再由管理员确认。请求进行中立即禁用按钮，防止双击产生第二次请求；完成后只刷新一次本地状态，不自动轮询或重试。

所有供应商派生文本使用 `textContent` 渲染。页面不得使用 `innerHTML` 展示响应内容，也不得把结果写入浏览器持久存储。

## 数据流

1. 管理员登录后，页面通过 `GET` 读取内存状态。
2. 管理员点击运行并确认固定调用成本。
3. 浏览器发送受 Origin、CSRF 和动作头保护的精确 `POST`。
4. HTTP 层调用 `marketProbeService.runFixed()`。
5. 服务先取得共享额度租约，再读取 refresh token、执行一次认证和最多三次顺序业务请求。
6. 客户端严格清洗响应，服务在租约仍属于当前运行时才发布内存结果。
7. HTTP 层返回防御性复制的 DTO；页面按未验证观察值展示。
8. 成功或失败均结算共享额度；不保存原始响应或规范化观察值。

## 失败处理

- 管理员认证、Origin、CSRF 或请求结构失败：不调用服务。
- 额度、冷却、并发租约或时钟检查失败：不读取秘密。
- refresh token、认证或任一业务请求失败：不重试，清零已拥有的令牌缓冲区并返回稳定错误码。
- 响应结构、字符、字段或尺寸不符合严格契约：拒绝整次结果，不发布部分观察。
- 租约过期、代际变化或清理竞态：丢弃迟到结果，不覆盖新的运行状态。
- 页面请求失败：保留上一次内存结果并显示本次失败，不用 Mock、旧案例或请求参数补齐。

## 测试设计

按照 TDD 实施，并先观察新增测试因入口缺失而失败。

### HTTP 与安全测试

- GET 不读取秘密、不消耗额度、不调用供应商。
- POST 要求管理员会话、精确 Origin、CSRF、JSON 和动作头。
- 家庭设备 Cookie、未登录、跨域、额外字段、查询参数和未知提案均被拒绝。
- 相同请求双击时只有一个服务运行；第二个请求得到忙碌或冷却状态。
- DTO 和错误响应不包含秘密、供应商 RequestId 或原始异常。

### 启动与清理测试

- disabled 模式不创建服务，也不读取 iFinD tmpfs。
- admin-diagnostic 模式注入固定服务和共享仓库。
- 启动失败、SIGTERM、SIGINT 和显式清理不会清除其他诊断服务拥有的客户端或结果。

### 前端测试

- 新卡片固定显示 Mock 边界、提案 ID、调用成本和七项未验证状态。
- 未登录或运行时不可用时按钮禁用。
- 点击确认后只发送一次 POST，运行中不能重复点击。
- 供应商派生内容只通过文本节点渲染，不进入 localStorage 或 sessionStorage。

### 回归检查

- 现有校准、报告期、三市场案例、家庭登录、设备审批和 Mock 家庭页面测试继续通过。
- `npm run check`、`verify`、`security` 和 `container-build` 全部通过。

## 发布与验收门

本设计对应的代码 PR 合并后仍不执行真实调用。

后续门槛依次为：

1. 用户批准离线候选镜像准备和导入；
2. 用户批准 disabled/admin-diagnostic 基线部署；
3. 管理员登录并确认页面状态；
4. 用户单独批准一次 `HK_ALIBABA_9988_V1` 真实探针；
5. 仅保存脱敏结果摘要，用于判断港股模板下一步是继续校准还是形成 no-go。

真实探针通过也只证明固定样本的响应结构可用，不自动证明任意港股、家庭展示或任何七维验证状态已经通过。

## 验收标准

- 管理员可以在独立卡片查看固定港股探针状态并执行一次明确确认的请求。
- 页面加载和状态读取不会产生 iFinD 调用。
- 每次执行最多一次认证和三次业务请求，零重试、并发一。
- 观察值仅在进程内存中，七维状态保持未验证，家庭页面继续使用 Mock。
- 新入口复用现有管理员安全边界和共享额度，不增加秘密、变量、表或部署协议。
- 日志、HTTP、SQLite、浏览器存储和部署状态中不存在 refresh token、access token、原始响应或 RequestId。
